# Maintainer process

This repository currently has one named code owner. The process keeps reviews, security reports, and release changes traceable without promising a response service level.

## Issue and pull request handling

1. Triage ordinary issues for affected version, platform, reproducibility, and user-data impact. Ask for a minimal reproduction with secrets and personal data removed.
2. Treat vulnerability reports as private. Follow [SECURITY.md](../../SECURITY.md); do not copy sensitive report details into a public issue or pull request.
3. Review changes against compatibility and data-migration requirements in [CONTRIBUTING.md](../../CONTRIBUTING.md). Check tests, documentation, and relevant build outputs before approval.
4. Merge only after required CI is successful and review comments are resolved. Keep Dependabot security update pull requests reviewable; automatic merging remains disabled.
5. Delete the merged feature branch when practical. Preserve release tags and published asset history.

## Dependency maintenance

Dependabot should monitor the active manifests and lockfiles in the root, frontend workspace, Python web-tools MCP, Node diagnostics MCP, NuGet solution, and GitHub Actions workflows. Security updates should arrive as pull requests. Review the affected runtime path and changelog, run the applicable regression and smoke tests, and update release inventory or notices when a shipped dependency changes. Major upgrades require a compatibility review; do not merge them solely to clear an alert.

## Release support

The latest Stable release is the supported baseline; older Stable versions are best-effort. Preview is an evaluation channel with best-effort support and no production availability or compatibility promise. See [SUPPORT.md](../../SUPPORT.md) and [release operations](releases.md).

Stable tags use `vX.Y.Z` and are created by a maintainer after a matching Preview has been evaluated. Preview tags use `vX.Y.Z-preview.N` and are generated by the scheduled release workflow. Never move or delete a published tag; fix releases forward with a new version. The proposed update/delete rule covers all `v*` tags, including unpublished tags, and has no bypass actors; an unrecoverable unpublished release therefore needs a reviewed fix-forward tag rather than tag deletion. See the [proposed tag rulesets](tag-ruleset-proposal.json) for a review-only policy design.

## Recommended repository settings

These are recommendations for an owner to review; this document does not change repository settings.

- Delete merged head branches automatically.
- Require sign-off for commits made through the GitHub web interface.
- Enable Dependabot security update pull requests.
- Keep Dependabot auto-merge and repository auto-merge disabled.

After enabling a setting, read it back in GitHub and record the result in the private release-readiness checklist.
