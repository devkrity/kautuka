# Broker security and branding follow-up

This plan tracks the independent review of the deployed broker and the loss of branding in the current sign-in flow. Work is on `fix/broker-security-and-branding` in both repositories. Do not publish or deploy as part of local implementation without the corresponding release authorization.

- [x] Restore the established Kautuka appearance to the active handoff and callback pages. Retain the destination, provider, purpose, operator-access notice, accessibility and responsive behavior. Preserve flow binding, exact-origin messages, URL clearing, denial and retry handling; do not re-enable the retired flow or imply operator verification. Verified rendered desktop and mobile pages under the production CSP, long origins, waiting/ready, rejected and invalid-callback states, plus handoff behavior tests. No real-provider callback was performed in this pass.
- [x] Enforce the intended canonical broker origin policy independently of the Gateway: HTTPS or supported private/loopback/local HTTP origins. Derive the policy from the established implementation; retain LAN access. Test invalid public HTTP origins and canonicalization attacks at both validator and signed public flow endpoint; ensure rejected requests create no flow.
- [x] Upgrade the compatible Wrangler/Miniflare/undici development dependency chain, inspect the lockfile and audit, and run broker unit, router and public Durable Object race tests. Full npm audit reported zero vulnerabilities; the affected chain is development tooling, not demonstrated production Worker exposure.
- [x] Set least-privilege token permissions in the Kautuka quality and secret-scan workflows and disable persisted checkout credentials where unnecessary. Validate required job permissions and add a meaningful policy regression check. YAML and local policy checks pass; GitHub CI will verify actual job execution after a later push.
- [x] Document separately how to recover from a lost installation key and respond to a stolen key. A new identity does not revoke the compromised one; describe provider grant revocation, currently available operator actions and their limitations. Do not create a public identity-reset or unauthenticated revocation endpoint.
