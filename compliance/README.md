# Release third-party compliance

`third-party-components.json` is the reviewed source of truth for components that are copied into Kautuka releases but may not be discoverable as ordinary packages (currently sqlite-vec, pinned runtime sidecar images, fonts, Photino.Native, and separately reviewed elkjs source/license evidence). Update it when versions, image digests, source commits, npm integrity values, or license evidence change. The release generator fails closed on changed sqlite-vec/elkjs license hashes, unknown runtime images, stale runtime digests, or an elkjs version/integrity mismatch.

Every release build runs `scripts/generate-third-party-compliance.mjs` with the frozen frontend production install present. It writes `THIRD_PARTY_NOTICES.txt`, `THIRD_PARTY_COMPONENTS.json`, `FRONTEND_DEPENDENCIES.json`, and applicable package-specific license/notice texts. The frontend inventory records the installed production dependency graph and hashes every present package license/notice file; standard SPDX license texts are added by the release credits step from a pinned SPDX License List revision. The frontend graph is a conservative superset and can include packages declared for frontend build use. These compliance materials are included in the Linux platform archive, WSL appliance filesystem, and release downloads. The Windows installer download receives the shared release compliance bundle during publication.

The publish workflow extracts the exact Linux platform and WSL appliance payloads and scans them with Syft `v1.55.0`. It publishes SPDX JSON beside the downloads for the Linux platform, WSL appliance, both bundled sidecar images, and the exact `kautuka-base` image digest used for that release. The SBOMs describe packages Syft can identify in those payloads; the component inventory retains exact source and digest evidence for bundled native libraries and OCI images.

Each release stages complete source archives for OpenObserve, git-pkgs/proxy, and both elkjs versions in the frontend dependency graph (direct 0.12.0 and Mermaid-transitive 0.9.3) at the exact commits recorded in the component catalog. It also stages source RPMs for the installed Fedora packages in the WSL rootfs and exact `kautuka-base` image. The elkjs archives accompany their EPL-2.0 license texts and source retrieval directions. The archives are published beside release binaries; `SOURCE_ARCHIVES.md` and `SHA256SUMS` describe and verify them.

When adding a new distribution artifact or a new embedded image, update the build workflow to generate and publish its SBOM and make sure that artifact receives the notices and applicable license texts. Review license obligations for the actual distribution before publication; the automation records evidence and flags drift but does not make a legal determination.
